# SupportAI AI Chat and Deployment Notes

## AI chat

The customer dashboard shows a floating SupportAI chatbox. It sends authenticated requests through the existing Axios client to the backend; the Groq key stays on the backend.

Request: `POST /api/chat`

```json
{
  "message": "How do I create a support ticket?",
  "history": [
    { "role": "assistant", "content": "Hi! How can I help?" }
  ]
}
```

`history` is optional. It accepts up to 20 prior `user` or `assistant` messages. The response remains:

```json
{
  "reply": "Open Create Ticket, describe the issue, choose a category, and submit it."
}
```

The endpoint still requires a logged-in user's JWT. It calls Groq's OpenAI-compatible chat-completions endpoint with `openai/gpt-oss-20b` by default. Groq documents that endpoint and model in its [API reference](https://console.groq.com/docs/api-reference) and [supported model list](https://console.groq.com/docs/models).

For local mock replies, set `GROQ_MOCK_ENABLED=true`. For real replies, set `GROQ_API_KEY` in the backend environment and keep mock mode off. `GROQ_API_MODEL` can override the model. The mock chatbot remains intent-based and does not use conversation history.

The chatbot offers guidance only. It does not create or modify tickets. Chat history exists in the open browser page and is sent to the backend for context; it is not stored as a conversation in the database.

## Run locally

1. Start the existing local MySQL server and make sure `tms` is available.
2. In IntelliJ's Run Configuration, keep the existing local database, JWT, and Google OAuth settings. Add `GROQ_MOCK_ENABLED=true` for a key-free mock run, or set `GROQ_API_KEY` for real Groq replies. Do not put secrets in Git.
3. In IntelliJ Terminal, run the backend from the repository root:

   ```powershell
   .\mvnw.cmd spring-boot:run
   ```

4. In a second terminal, run the frontend:

   ```powershell
   cd frontend
   npm ci
   npm run dev
   ```

The local API defaults to `http://localhost:8080/api`; the frontend defaults to `http://localhost:5173`.

## Verify the chat API with Postman

Use a valid logged-in user's JWT as a Bearer token:

- Method: `POST`
- URL: `http://localhost:8080/api/chat`
- Header: `Content-Type: application/json`
- Body: raw JSON with a `message` (and optional `history`)

Expect HTTP 200 and a JSON `reply`. With real Groq mode, this verifies the external API connection. With mock mode, it verifies only the local endpoint and mock response. Do not send API keys or tokens in chat messages or source control.

## Render deployment

The root `render.yaml` defines a Docker web service for Spring Boot and a static site for the React/Vite frontend. The frontend gets the backend URL from Render at build time. The backend gets its frontend URL and CORS origin from the static service URL. `Dockerfile` builds the existing Maven project and runs its packaged JAR; `.dockerignore` excludes local properties and build artifacts.

The backend blueprint uses Render's free web plan, which may sleep when idle and take time to wake. The React static site is served separately. Production ticket data must live in an external MySQL server; Render does not provision that database in this blueprint.

Provide these values in Render's service environment when creating the Blueprint:

| Variable | Purpose |
|---|---|
| `DB_URL` | JDBC URL for the external MySQL database, for example `jdbc:mysql://HOST:3306/DATABASE` with any SSL options required by the provider |
| `DB_USERNAME` | Database user |
| `DB_PASSWORD` | Database password |
| `GROQ_API_KEY` | Groq secret key |
| `GOOGLE_CLIENT_ID` | Google OAuth client ID |
| `GOOGLE_CLIENT_SECRET` | Google OAuth client secret |

`APP_JWT_SECRET` is generated by the Render Blueprint. Do not share database or provider secrets in chat or commit them to the repository. The frontend URL, API URL, CORS origin, and OAuth success callback are wired from Render service URLs.

After the backend URL is assigned, add this authorized redirect URI to the Google OAuth client (replace the host with Render's actual backend URL):

```text
https://supportai-api.onrender.com/login/oauth2/code/google
```

The Google success handler then redirects to the frontend's `/oauth2/callback` route. Keep `GROQ_MOCK_ENABLED=false` in Render so the deployed chat uses Groq.
